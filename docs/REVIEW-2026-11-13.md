# Payment preparation and checkout review fixes

## Scope

- **Checkout invoice identity (Front):** fragment changes and browser history now re-verify the signed invoice. A new invoice mounts a fresh payment workspace, clearing the previous API trust, payer, operation review and unlocked journal state. Stale signature-verification results are discarded; unmount locks the previous in-memory journal. The payment-section shortcut scrolls without replacing the signed invoice fragment.
- **CLI vault selection (Core):** automatic deposit/withdrawal preparation scans every catalog page at one finalized block. It fails explicitly above the default 1,000-record budget instead of choosing from a partial group. Explicit vault selection uses `get_vault`, checks the corresponding registry page, then applies the same contract/key/configuration/eligibility checks. Deposit preparation accepts an optional final vault account; withdrawal actions retain their `vault` field. The paginated discovery API remains available for browsing.
- **Historical invoice tests (Core):** the public-plan binding test uses the historical fixture's clock. Production expiry checks and signed fixture terms remain unchanged.

## Regression coverage

- Native and FT groups with 205 vaults and withdrawal liquidity only in the last record; every page read uses one finalized block.
- Explicit selection beyond the 1,000-record budget; foreign/mismatched records, unsafe contracts, pending vaults and inconsistent snapshots fail verification or remain ineligible.
- CLI FT deposit preparation against a local JSON-RPC fixture verifies a selected vault at index 204, including code hashes and the checked block.
- Browser checkout transitions with an imported plan, back/forward navigation, invalid fragments, payment-section scrolling and a delayed older signature result, on desktop and mobile Chromium.
- Invoice privacy tests also run with the wall clock after the historical invoice's expiry. These tests use fixtures; they do not establish public-network deployment or live payout success.
